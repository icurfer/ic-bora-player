# Bora UI 검토

사용자가 파일을 보면서 메모하고 편집하며 대화하는 흐름을 유지한다. 화면의 장식보다
현재 파일·작업·대화 상태를 구별할 수 있는지, 조작 결과가 예측 가능한지를 검토한다.

## 먼저 고정할 맥락

- 저장소 `CLAUDE.md`, 해당 변경의 최신 기획서·범위를 읽는다. 현재 UI의 실제 실행 화면과
  `src/bora/window.py`, `src/bora/notes/panel.py`, 변경 대상 위젯을 대조한다.
- GTK4 + **libadwaita 1.1 범위**를 지킨다. 새 위젯은 설치된 최신 버전에서만 되는 것으로
  만족하지 말고 도입 버전을 확인한다. 웹 라이브러리로 앱을 바꾸지 않는다.
- 디자인 맥락을 검토 결과에 짧게 남긴다: 주 작업, 보조 작업, 기존 위젯·아이콘,
  간격·본문 크기, 강조/오류 표현, 최소 창 크기와 패널 폭. 소스와 화면에서 확인한 것과
  제안을 구분한다. 기존 Adwaita 의미 클래스와 시스템 글꼴을 우선 사용한다.
- 새 색상표·브랜드·전면 재설계는 별도 요청이 있을 때 다룬다. 기존 간격이 쓰임에 따라
  다른 것을 무조건 오류로 취급하거나, 픽셀값 사용 자체를 금지하지 않는다.

## 설계와 독립 검토

구현 전에는 변경되는 사용자 흐름과 필요한 상태를 정의하고, 구현 중에는 동작하는
중간 화면을 검토한다. 구현 후에는 실제 조작으로 다시 확인한다. 사용자가 디자인
에이전트를 요청했거나 위임이 허용된 작업에서는 구현 담당과 검토 담당을 나눈다.
검토 담당에게 이 스킬, 사용자 목표, 실제 변경 파일·실행 방법을 전달한다.
불필요한 추가 에이전트나 외부 디자인 서비스를 자동 생성하지 않는다.

문제는 `심각도 | 재현 동작 | 관찰 결과 | 근거 | 수정 방향`으로 전달한다.
취향만으로 출시 차단 사유를 만들지 않는다. 수정 후 해당 동작을 재검토하고 판정을 갱신한다.

## Codex 대화에 적용할 동작 계약

- 사용자 확정 배치: 오른쪽 위 메모, 아래 Codex를 동시에 표시하는 세로 분할. 탭으로 서로 숨기지 않는다. 경계선으로 높이를 조절하고 두 입력 영역의 접근성을 실제 확인한다.

- 사용자는 메모와 대화를 구분할 수 있어야 한다. 대화 답변이 사용자가 작성 중인 메모를
  자동으로 덮거나 커서를 빼앗지 않는다. 답변을 메모에 옮기는 동작은 명시적으로 제공한다.
- 현재 파일·질문에 포함되는 재생 시각, 자막, 선택 메모를 알 수 있게 한다. 파일을 바꿨을 때
  이전 답변이 새 파일의 대화나 메모에 들어가지 않는지 확인한다.
- Codex 미설치, 로그인 필요, 연결 확인 중, 준비됨, 답변 중, 중지됨, 실패/사용 한도 상태를
  구분한다. 오류에는 다음 행동을 함께 제공하고, 설정이나 질문 초안을 잃지 않게 한다.
- 비용 관련 표현은 실제 인증 경로에 맞춘다. ChatGPT 로그인 이용을 무제한 무료나
  오프라인 모델이라고 쓰지 않는다. 별도 API 키 입력과 유료 API 자동 전환을 요구하지 않는다.
- 전송·중지·재시도·새 대화·메모에 넣기는 의미가 드러나는 이름을 쓴다. 제공하지 않는
  동작은 가짜 버튼으로 채우지 않는다. 답변 중에도 재생·메모 편집·취소가 가능해야 한다.
- 긴 한국어 질문, 여러 문단 답변, 코드·긴 경로에서도 본문이 창 밖으로 밀리지 않게 한다.
  사용자가 위쪽 대화를 읽고 있으면 스트리밍이 스크롤을 강제로 아래로 보내지 않게 한다.

## 실제 검증 게이트

기존 [verify-app](../verify-app/SKILL.md)의 시나리오와 격리 방법을 사용한다.
사용자의 재생 세션, 최근 파일, 메모, 로그인 설정을 시험 데이터로 바꾸지 않는다.
인증·실패·지연은 가짜 응답으로 재현할 수 있으며, 실제 서비스 호출과 구분해 기록한다.

| 게이트 | 확인할 증거 |
|---|---|
| 창 배치 | 기본 창과 실제 지원 최소 크기에서 영상·메모·대화 조작이 가려지지 않음. 요청 크기와 실제 할당 크기를 함께 기록 |
| 상태 | 빈 화면, 준비, 답변 중, 중지, 오류 화면을 실행해 캡처. 구현된 상태가 사용자의 다음 동작으로 이어짐 |
| 키보드 | Tab/Shift+Tab으로 입력·전송·중지·닫기에 접근. 입력 중 Space/화살표가 재생 단축키로 새지 않음. 대화창 닫은 뒤 포커스 복귀 |
| 가독성 | 실제 지원하는 테마에서 한국어 긴 글·상태 문구·선택·포커스 식별. 색만으로 오류를 표현하지 않음 |
| 데이터 보존 | 전송/중지/실패/파일 전환/재시도 뒤 질문 초안, 사용자 메모, 영상별 대화가 계약대로 보존됨 |
| 재생 회귀 | 대화 응답 중에도 기존 재생·탐색·메모 편집 가능. 창 닫기·파일 전환 뒤 늦은 응답이 새 작업에 반영되지 않음 |

GTK 위젯 이름과 접근성 역할, 텍스트가 있는 동작 버튼을 확인한다. 아이콘 전용 버튼은
의미를 알 수 있는 툴팁/접근성 이름을 제공한다. 스크린 리더로 직접 시험하지 않았다면
접근성 전체 통과라고 쓰지 않는다. 웹 axe 결과를 GTK 접근성 증거로 쓰지 않는다.

스크린샷은 실제 GTK 실행 결과를 본다. HTML 목업, 소스 검사, 자동 테스트 통과만으로
시각 검토 완료라고 하지 않는다. GUI 접근이 없으면 가능한 소스 검토를 수행하고
실측 불가 항목을 명시한다. 캡처에는 개인 경로·메모·로그인 정보 대신 격리된 샘플을 쓴다.

## 판정

- **수정 필요**: 주요 버튼 접근 불가, 글 잘림으로 기능 불명, 응답 중 앱 정지,
  메모 손실, 파일 간 대화 혼입, 비용/인증 경로 오해 같은 재현 가능한 결함.
- **통과**: 요청한 주요 흐름이 실제로 동작하고 차단 결함이 없음. 사소한 개선은 따로 기록.
- **미검증**: 화면이나 서비스에 접근하지 못한 부분. 통과 수에 포함하지 않는다.

검토 보고에는 실행 환경, 화면 크기·테마, 테스트 명령/결과, 캡처 경로, 남은 결함을 남긴다.
단순한 외형 점수나 임의의 총점으로 동작 결함을 상쇄하지 않는다.
