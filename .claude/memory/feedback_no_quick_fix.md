(STARTER RULE — 맞으면 남기고 아니면 지운다.) 원인 파악을 건너뛰는 "빠른 수정"에 손대지 않는다.
코드 변경은 진단 → 가장 작은 올바른 변경 결정 → 구현 순서다. 빠르지만 근거가 약한 우회책을
선택지로 제시하지 않는다. "코드만 먼저 고치고 문서는 나중에"도 같은 종류의 우회다.

**왜:** 진단을 건너뛴 지름길은 증상을 가리고, 되살아났을 때 비용이 더 크다.
**적용:** 급히 때우고 싶을 때일수록 원인을 먼저 확정한다([[feedback_diagnose_before_assume]]).
임시방편을 적용하기 직전이 가장 위험한 지점이니, 그 진단으로 모든 관찰이 설명되는지 자가 검증한다.
