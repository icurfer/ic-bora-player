`.claude/skills/verify-app/scenarios/` 는 실제 앱을 띄워 검사하지만 **세 가지를 구조적으로
못 본다.** 전부 실기에서 결함이 나온 뒤에야 알았다(작업내역 `docs/done/done-v0.22.0-2026-09-20.md` §2).

1. **기능을 직접 부르면 키 경로를 보지 못한다.** `win.toggle_pause()` 를 부르는 검사는
   통과하는데 `Space` 는 죽어 있었다(포커스된 버튼이 먼저 먹었다). 단축키는 반드시
   `win._on_key(...)` 로 **키 경로**를 타고, 포커스를 버튼에 둔 채로 검사한다.

2. **위젯 상태는 "보인다"를 뜻하지 않는다.** `get_visible()`·`get_reveal_child()` 가 True 여도
   화면 밖일 수 있다. 메뉴가 창보다 길어 팝오버가 아예 안 뜬 적이 있다 — **크기를 창 크기와
   비교**하고, 팝오버는 네 귀퉁이에서 좌표를 재야 잡힌다.

3. **검증 환경에서는 창이 매핑되지 않는다.** 백그라운드로 띄운 창은 위젯 폭이 0 이고
   `draw` 가 한 번도 불리지 않는다. 그리기 결과(필름스트립 등)는 **이 환경에서 확인할 수 없다.**
   → 그리기 통계를 debug 로그로 남겨 두면 사용자 로그 한 줄로 갈린다.
   → `draw` 안에서만 하는 일(리소스 요청 등)을 두지 말고 `load()` 같은 진입점에서도 한 번 한다.

**How to apply:** GUI 기능을 만들면 위 셋 중 무엇에 걸리는지 먼저 따지고, 자동으로 못 잡는
부분은 (a) debug 로그를 남기고 (b) 사용자에게 "이건 눈으로 봐 주셔야 한다"고 분명히 말한다.
"통과했으니 된다"고 보고하지 않는다. [[feedback-verify-before-done]]
