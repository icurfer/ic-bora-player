# task 관리 정책 적용

포탈 task **350**, ic-bora 스페이스 **26**, 로컬 하네스 `task-management`.

## 반영

- `.claude/task-space`에 기본/허용 대상을 26으로 제한. 에이전트 공통 파일에 계정 강제 없음.
- `docs/TASK_MANAGEMENT.md`에 접수·중복 확인·착수·상태·인계·완료·접속 실패 절차 작성.
- AGENTS.md/CLAUDE.md 공통 지침과 praxis 진입점 연결.
- Linux와 Windows 수용 기준, 포탈 상태와 로컬 검사 상태, 설치/배포 상태 구분.

## 확인

Codex 명의로 실제 스페이스와 멤버십을 조회했다. 스페이스26에 사용자와 Codex가 있고,
기존 task가 없어 실제 정책 작업 350 한 건만 등록했다. 조회에서 제목·담당·대상·상태를
확인했다. 기본 목록이 26으로 제한되며 범위 밖 대상25 등록 시도는 로그인 전 exit3으로
거부됐다. 다른 스페이스나 검증용 task를 생성하지 않았다.

정책 작업에 인계 댓글과 review 상태를 기록한다. 최종 검사·커밋·push를 확인한 후 같은
task에 커밋과 결과 댓글을 남기고 done으로 전환한다. 최종 외부 상태는 포탈 상세가 정본이다.
코드와 제품 버전은 변경하지 않으며 문서/대상 선언 검증을 위해 기존 하네스 검사를 실행한다.
이 문서 변경은 패키지 배포나 로컬 설치를 요구하지 않는다.

## 남은 범위

Windows 머신의 helper·자격·실제 접속, Claude 멤버십은 미검증/미구성이다.
기존 백로그 대량 이관, 자동 알림·상시 동기화, 초대·권한 변경은 수행하지 않았다.
task-register의 기존 범위 검사와 계정별 접근 권한을 사용하며 별도 서버 변경은 없다.
