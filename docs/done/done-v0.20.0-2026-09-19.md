## §1 v0.4 가 틀린 곳

기획서 v0.4 §0-1 에 "타임라인 편집기를 만들지 않는다. 그건 Kdenlive 의 일"이라고 적었다.
**이 선이 잘못 그어졌다.** 사용자가 원한 것은 Kdenlive 가 아니라 보면서 그 자리에서 자르는 띠였다.

| 목록으로 안 되던 것 | 타임라인에서 |
|---|---|
| 전체 중 어디를 담았는지 안 보인다 | 필름스트립 위에 구간이 보인다 |
| 담은 뒤 경계를 못 만진다 | 끝을 잡고 끈다 (이웃이 따라 준다) |
| 결과를 미리 못 본다 | 미리보기가 남은 구간만 이어 재생한다 |
| 담기(keep)만 있다 | **기본이 잘라내기(cut)** 로 바뀌었다 |

마지막이 가장 큰 변화다. 처음에 영상 전체가 구간 하나로 놓여 있고, 자르고 **지워서** 남길 것을
만든다 — 강의에서 잡담을 걷어내는 쪽이 훨씬 흔하기 때문이다.

## §4 계측·환경이 먼저 틀린 곳

**4-1. `python3-gi-cairo` 가 없어 아무것도 그려지지 않았다.**
`Couldn't find foreign struct converter for 'cairo.Context'` — `python3-cairo` 는 있었지만
PyGObject 와 잇는 브리지(45 KB)가 빠져 있었다. `DrawingArea` 를 처음 쓴 탓에 이제껏 드러나지
않았다. 설치하고 **deb 의존에 넣었다** — 이게 빠지면 설치본에서 타임라인이 통째로 비어 보인다.

**4-2. draw 에 기대어 썸네일을 요청한 것이 약했다.**
처음엔 그릴 때 보이는 범위를 계산해 요청했는데, 창이 완전히 매핑되기 전에 타임라인을 열면
`draw` 가 불리지 않아 **필름스트립이 영영 비어 있었다**(위젯 폭 0, `child_revealed=False`).
같은 코드가 실행마다 되기도 하고 안 되기도 했다 — 경쟁 조건이었다.
→ `load()` 시점에 폭과 무관하게 초기 요청을 보낸다. 그릴 때의 요청은 그 위에 얹는다.
