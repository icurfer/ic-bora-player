# 버전·릴리스 정책 전환 — 2026-10-09

## 변경

- SemVer 기반 정책을 docs/RELEASING.md 한 곳에 정의하고 0.x 호환성 기준을 명시했다.
- AGENTS.md를 추가하고 CLAUDE.md의 공통 블록을 동기화했다. 과거 메모의 자동 bump 규칙도 정정했다.
- 코드/문서 변경마다 버전 수정을 강제하던 Gate A를 제거했다.
- 필수 정책 파일, 제품 버전 형식, 공통 지침 불일치, 설치 바이너리 Git 추가를 검사한다.
- version_policy.py가 개발 버전 식별, Debian 후보 표기 변환, 태그/HEAD/깨끗한 트리/CHANGELOG/검증 기록을 검사한다.
- version은 미출시 작업본임을 표시하는 0.26.6-dev.1이다. 새 정식 버전은 만들지 않았다.
- 사용자 정정에 따라 추가했던 GitHub Actions CI와 자동 릴리스 workflow를 제거했다. 로컬 검사·빌드와 수동 Release 업로드로 정리했다.
- 과거 dist deb는 추적만 해제했다. 파일과 Git 과거 이력은 보존하고 과거 다운로드 링크는 커밋에 고정했다.
- 새 기획 문서는 주제명, 완료 문서는 주제/날짜를 쓰며 제품 버전과 구분한다.

## 검증

- 버전정책 회귀 21개 통과: 버전 문법, Debian 후보 정렬, 코드/문서의 무-bump 커밋,
  staged 오류를 작업트리 수정으로 숨기지 못함, 규칙 불일치/바이너리/필수파일 삭제 차단,
  태그 불일치/dirty/미검증 기록 차단, 개발 식별자.
- 기존 AI·이미지·메모·상태 관련 검사와 합계102개 통과.
- Bash 문법 검사 통과.
- 개발 deb 실제 빌드 성공. dpkg Version과 내장 앱 버전의 명시적 변환 일치 확인.
- Python PEP440 개발 버전 정규화 확인.
- 실제 태그 생성과 Release 공개는 수행하지 않았다.

## 범위와 한계

이 작업의 통과는 이전 이미지/단축키 GUI E2E 통과를 뜻하지 않는다. 해당 항목은 별도 인계에 남겼다.
릴리스 기록의 passed 표기는 실제 검사한 사람이 증거와 함께 작성해야 한다. 스크립트는 표기만 검사한다.
GitHub의 공개 Release는 조회 당시 없었지만, 과거 Git에 공개한 패키지 버전은 재사용하지 않는다.
