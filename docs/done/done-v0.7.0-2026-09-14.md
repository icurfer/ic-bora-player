## §3 자막 에디터 — 이 버전의 중심

**왜 만들었나**: 조사해 보니 편집기(Aegisub·Subtitle Edit)는 재생 중 타이밍을 찍을 수 있지만
감상용이 아니고, 플레이어(팟플레이어·VLC·mpv)는 전체 오프셋만 밀 수 있고 **저장이 안 된다.**
"보다가 어긋난 줄 하나를 그 자리에서 고치고 저장"이 빈 자리였다.

```
자막이 늦다 → [Space] → [E] → 지금 화면의 큐가 이미 잡혀 있다
  → [현재 위치를 시작으로]  → [이 줄부터 뒤로 -2초]  → [저장]
  → .bak 남기고 저장 → 플레이어에 다시 물려 화면에 바로 반영
```

- **현재 큐 잡기**: 재생 위치에 걸린 큐, 없으면 **직전 큐**(자막이 늦게 뜨는 경우가 흔하다)
- **밀기**: 전체 / 이 줄부터 뒤로(국내 자막에서 가장 흔한 형태)
- **싱크값 가져오기**: 플레이어에서 맞춰 둔 `sub-delay` 를 파일에 굳히고 delay 를 0 으로 되돌린다
- **저장 정책**: 덮어쓸 파일이 있으면 `.bak` 으로 **복사**. SAMI 는 `.srt` 로 내보내고 원본은 그대로.
  분리 트랙은 캐시가 아니라 **영상 옆 `<영상이름>.<언어>.srt`** 로 저장한다
- **하지 않은 것**(기획서 §2-4 대로): 오디오 파형, ASS 스타일 편집, 자동 자막 생성

## §5 잡은 결함

| # | 결함 | 원인 | 왜 늦게 드러났나 |
|---|---|---|---|
| 1 | **절대 seek 가 0 으로 되감김** | `python-mpv` 의 `seek(x, reference='absolute')` 래퍼. 9.0초 → 0.80초, 예외 없음 | 기존 검증이 **우연히** 통과했다 — 탐색은 상대 seek 였고, 정지는 어차피 0 으로 가니 맞아떨어졌다. 절대 seek 가 처음 진짜로 쓰인 자막 에디터에서 드러났다 |
| 2 | 우클릭 메뉴가 좌상단에 뜸 | `Gdk.Rectangle(x=…)` 생성자 키워드가 조용히 무시돼 (0,0) | 전체화면에서는 화면 밖이라 "안 뜬다"로 보였다 |
| 3 | 분리 트랙 편집본이 캐시에 저장 | 읽은 곳과 저장할 곳을 같게 봤다 | E4 수용 테스트가 잡았다 |
| 4 | 1밀리초짜리 큐가 남음 | `end <= start` 로 판단. '겹쳤는가'가 아니라 '충분히 긴가'로 봐야 했다 | 단위 테스트가 잡았다 |
| 5 | `srt_to_ms('1:30')` → 30초 | 옵션 그룹 두 개짜리 정규식의 탐욕 매칭 | 단위 테스트가 잡았다 |

1~2번은 [`../research/2026-09-14-pygobject-mpv-traps.md`](../research/2026-09-14-pygobject-mpv-traps.md) 에 정리했다.
**셋 다 예외 없이 그럴듯하게 틀린 값을 돌려준다** — 기대값을 단언하는 테스트가 유일한 방어였다.
