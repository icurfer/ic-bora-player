# 실측 기록 5 — 실제 자막에서 나온 결함: 엔티티만 있는 큐 (2026-09-14)

**deferred §4 에 "미루되 잊지 않는다"고 적어 둔 '실제 자막 표본 검증'이 첫 사례로 실행됐다.**
사용자가 실제 영화와 자막을 넣고 "자막이 안 나온다"고 보고했고, 그 진단 기록이다.

표본: `Inside Out (2015) 1080p BluRay x265 10bit` (4.4 GB MKV) + 동명 `.srt` (155 KB)
※ 표본 자체는 저장소에 넣지 않는다(`/sample/` 은 `.gitignore`).

## 0. 결론

**자막이 "안 나온" 것이 아니라 `&nbsp;` 가 빈 칸으로 찍히고 있었다.**

| | |
|---|---|
| 증상 | 특정 구간에서 자막이 보이지 않는다 |
| 실제 | `sub-text` 가 `'&nbsp;'` — 화면에는 빈 칸이 그려진다 |
| 원인 | 이 SRT 는 **SAMI 를 변환한 것**이고, SAMI 의 종료 신호 `&nbsp;` 가 텍스트로 그대로 남았다 |
| 규모 | 총 2665 큐 중 **1332 개(50%)** 가 `&nbsp;` 단독 큐. 길이는 1 밀리초 |
| 처방 | mpv `--sub-filter-regex` 로 그 줄을 버린다. **파일을 다시 쓰지 않는다** |

이것을 **P5** 로 기획서 §2 에 추가했다.

## 1. 진단 과정 — 어디서 끊기는지 순서대로

추정하지 않고 단계별로 좁혔다.

```
① find_sidecar  -> 자막 파일을 찾았다 (공백·괄호가 든 이름도 정상)
② detect        -> UTF-8 (BOM 있음), confident=True, codepage '+utf-8'
③ Plan          -> split=False (SAMI 가 아니므로), 인코딩 주입만
④ 실제 재생     -> sid=7 (외부 .srt) selected=True   ← 선택도 정상
                   sub-text = '&nbsp;'                ← 여기서 드러났다
```

①~③ 이 전부 정상이라 "자막을 못 찾는다/인코딩이 틀렸다"는 가설은 모두 배제됐다.
**화면에 나오는 값을 직접 본 것이 결정적이었다.**

곁가지로 확인된 것: 이 MKV 에는 내장 자막 트랙이 6개(dvd_subtitle, eng/fre/spa) 있다.
외부 `.srt` 가 sid=7 로 붙고 자동 선택된다 — 트랙 경쟁 문제는 없었다.

## 2. 자막 파일의 실제 모양

```
1
00:00:01,500 --> 00:00:11,481
자막 및 번역팀
Team Paraphilia

2
00:00:11,481 --> 00:00:11,482        <- 1 밀리초
&nbsp;                               <- 이것이 화면에 빈 칸으로 찍힌다

3
00:00:11,482 --> 00:00:16,514
자막:으잌㉪
```

- 엔티티 종류: `&nbsp;` 하나뿐 (1332 회)
- HTML 태그: 없음
- 즉 **SAMI → SRT 변환기가 태그는 지웠는데 엔티티는 남겼다.** 국내 자막에 흔한 형태다.

## 3. 처방 — 파일을 다시 쓰지 않는다

mpv 에 `--sub-filter-regex` 가 있다(POSIX ERE, 줄 단위). 실측:

| 시각 | 필터 없음 | 필터 적용 |
|---|---|---|
| 51.6 s | `'&nbsp;'` | `''` ✅ |
| 11.9 s | `'자막 및 번역팀 / Team Paraphilia'` | 그대로 ✅ |
| 217.5 s | `'좋아, 주의 / 위험한 냄새가 난다구'` | 그대로 ✅ |

쓰는 패턴 (`loader.EMPTY_CUE_REGEX`):

```
^(&nbsp;|&#160;|&#xa0;|\s)*$
```

줄 전체가 엔티티·공백뿐일 때만 버린다. 파일에 해당 엔티티가 하나도 없으면 필터를 켜지 않는다.

**설계 원칙이 유지된다** — 기획서 §5-2 의 "인코딩은 파일을 다시 쓰지 않는다"에 이어,
빈 큐 정리도 옵션 주입으로 끝난다. 파일을 만드는 것은 여전히 **한·영 통합 SAMI 일 때뿐**이다.

## 4. 함께 드러난 것 — 로그가 없었다

이 버그를 눈으로 볼 수단이 없었다. `really_quiet=True` 로 libmpv 로그를 전부 끄고 있었고
앱 자체 로그도 없어서, 매번 파이썬을 띄워 프로퍼티를 찍어 봐야 했다.

→ `src/bora/log.py` 추가. `--debug` 또는 `BORA_DEBUG=1` 로 앱 로그와 **libmpv 로그를 함께** 본다.

```
$ BORA_DEBUG=1 PYTHONPATH=src python3 -m bora <파일>
DEBUG [bora.subtitle] 자막 ...srt: 엄격 UTF-8 디코드 성공 (엔티티 큐 1332개)
INFO  [bora.subtitle] 자막 계획: UTF-8 · 빈 큐 1332개 정리 (...srt)
INFO  [bora.player] 열기: ...mkv (codepage=+utf-8, sub-auto=fuzzy, 필터=1개)
```

`BORA_LOG_FILE=/tmp/bora.log` 를 주면 파일로도 남는다.

## 5. 아직 확인하지 않은 것

- 다른 변환기가 남기는 **다른 엔티티**(`&amp;`, `&quot;`, `&#13;` 등)와 `<br>` 잔재.
  지금 필터는 `&nbsp;` 계열만 본다. 실제 표본이 더 모이면 넓힌다.
- `&nbsp;` 가 **문장 안에** 섞인 경우(줄 전체가 아닌). 지금은 그대로 둔다 —
  공백으로 바꿔 주는 편이 나을 수 있으나 표본이 없다.
- 1 밀리초짜리 큐가 mpv 에서 어떻게 처리되는지. 필터로 지워지니 지금은 문제가 아니다.
