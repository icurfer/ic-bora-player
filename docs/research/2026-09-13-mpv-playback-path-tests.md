## 1. mpv 옵션만으로 어디까지 되나 (§8-6)

`man mpv` 의 `--sub-codepage` 절이 명시하는 **판정 순서**(v0.41 기준):

1. 코드페이지에 `+` 가 붙어 있으면 그것을 강제
2. 데이터가 UTF-8 처럼 보이면 UTF-8
3. `--sub-codepage` 가 특정 코드페이지로 지정돼 있으면 그것을 사용
4. uchardet 실행, 성공하면 그 결과
5. 실패하면 `UTF-8-BROKEN` (UTF-8 로 읽되 깨진 바이트는 Latin-1 폴백)

→ **`--sub-codepage=+<enc>` 는 탐지를 완전히 우회한다.** 우리가 탐지한 결과를 이 옵션으로 주입하면
**자막 파일을 다시 쓰지 않고도** 인코딩 문제가 끝난다. 전처리기의 부담이 크게 준다.

같은 절에서 발견한 것: **`--sub-stretch-durations`**
("Stretch a subtitle duration so it ends when the next one starts. Should help with subtitles
which erroneously have zero durations.") — P4 를 완화하는 옵션이 mpv 에 이미 있다.

### 실측 (`probe2.py`) — libmpv 에 자막을 넣고 재생 중 `sub-text` 관찰

`sample_cp949.smi` (한·영 통합, KRCC+ENCC, 587 B):

| 옵션 | 1초 시점에 보이는 것 |
|---|---|
| 기본(auto) | `First subtitle line. / second line` — **한글 없음** |
| `--sub-codepage=+cp949` | `First subtitle line. / second line` — **여전히 한글 없음** |
| `+cp949` + `--sub-stretch-durations` | `첫 번째 자막입니다. / 두 번째 줄 / First subtitle line. / second line` — 한글은 나오지만 **한·영이 겹친다** |

`short_cp949.smi`(107 B, uchardet 이 1252 로 오탐하는 케이스), `styled_cp949.smi`(333 B):

| 옵션 | 결과 |
|---|---|
| auto | `¾È³çÇÏ¼¼¿ä` (모지바케) |
| `+cp949` | `안녕하세요` ✅ |

`mid_cp949.smi`(단일 클래스 SAMI), `plain_cp949.srt` 는 **네 조합 모두 정상**이다.
→ 단일 언어 자막은 인코딩만 맞으면 손댈 것이 없다.

## 2. 인코딩 판정 파이프라인 (§8-4)

### 2-1. 태그 제거의 효과는 기대와 달랐다

기획서 §5-2 ①은 "태그를 벗기면 오탐의 대부분이 사라진다"고 예상했다. 실측(`detect2.py`):

| 파일 | 원본 uchardet | 태그 제거 후 |
|---|---|---|
| `short_cp949.smi` (107 B) | WINDOWS-1252 ❌ | **(탐지 실패)** |
| `styled_cp949.smi` (333 B) | WINDOWS-1252 ❌ | **(탐지 실패)** |
| `tiny_cp949.smi` (57 B) | WINDOWS-1252 ❌ | WINDOWS-1252 ❌ |
| `bilingual_en_heavy_cp949.smi` (950 B, 영어 비중 큰 한·영 통합) | **UTF-8** ❌ | **UTF-8** ❌ |
| `mid_cp949.smi` · `plain_cp949.srt` · `sample_cp949.smi` | UHC ✅ | UHC ✅ |

**태그 제거는 오탐을 정답으로 바꾸지 않는다. "오탐"을 "실패"로 바꿀 뿐이다.**
그래도 가치가 있다 — 오탐을 그대로 믿으면 모지바케가 확정되지만, 실패로 떨어지면 다음 단계가 돈다.
그리고 영어 비중이 큰 한·영 통합 자막은 **UTF-8 로 오탐**된다(`+` 없는 지정으로는 못 막는다).

### 2-2. 한글 비율 검증 — 일본어를 절대 구분하지 못한다

비ASCII 문자만 분모로 잡고 cp949 로 디코드했을 때의 한글 음절 비율:

| 파일 | 실제 인코딩 | 비ASCII 수 | 한글 비율 |
|---|---|---|---|
| CP949 파일 전부 (7개) | cp949 | 1~140 | **1.00** |
| `ja_sjis.smi` | shift_jis | 154 | **1.00** ⚠ |
| `zh_gb18030.smi` | gb18030 | 98 | 0.50 |

**Shift_JIS 바이트열을 cp949 로 디코드하면 전부 유효한 한글 음절로 떨어진다.**
기획서 §7 이 "우선순위 낮음"으로 미뤄 둔 위험이 실측으로 확인됐다 — 한글 비율만으로는 구분이 **불가능**하다.
(중국어는 절반이 한자로 떨어져 구분 여지가 있다.)

→ **한글 비율 검증은 탐지기가 CJK 를 지목하지 못했을 때의 보조 수단으로만 써야 한다.**

### 2-3. 실측으로 확정한 판정 순서 (`pipeline.py`, 11/11 통과)

```
① UTF-8 로 엄격 디코드 성공 → UTF-8 확정
② 태그·엔티티·SRT 타임코드 제거 → uchardet
③ 결과가 CJK 계열(SHIFT_JIS/EUC-JP/GB18030/BIG5/EUC-KR/UHC)이면 그대로 신뢰
   — 한글 비율로 뒤집지 않는다 (2-2)
④ Latin 계열·UTF-8 오탐·탐지 실패 → cp949 디코드 후
   '비ASCII 중 한글 음절 비율 ≥ 0.7' 이면 CP949 확정
⑤ 그래도 못 정하면 cp949 폴백 + UI 에 "추정" 배지
```

③ 이 ④ 보다 **먼저** 와야 한다는 것이 이번 실측의 핵심이다.
②에서 UTF-8 이 나와도 ①이 실패했다면 믿지 않는다(2-1 의 한·영 통합 오탐 사례).

임계 `0.7` 근거: 측정된 CP949 자막은 전부 1.00, 중국어는 0.50. 한자가 섞인 한글 자막을 고려해
1.00 을 요구하지 않는다. **실제 자막 표본이 늘면 재검토할 값이다.**

> 바이트 단위 태그 제거가 안전한 이유: `<`(0x3C) `>`(0x3E) `&`(0x26) `;`(0x3B) 는
> CP949 · Shift_JIS · GB18030 의 2바이트 문자 trail byte 범위(0x40~0xFE)에 들어가지 않는다.
> 디코드 전에 잘라도 멀티바이트 문자를 쪼갤 위험이 없다.

## 3. SAMI 클래스 분리 (§5-2 ② 설계 검증)

`sami_split.py` — `<SYNC Start>` / `<P Class>` 를 파싱해 클래스별 SRT 로 나눈다.
큐 끝은 **같은 클래스의 다음 SYNC**, `&nbsp;` 단독 큐는 출력하지 않고 종료 신호로만 쓴다.

`sample_cp949.smi` 분리 결과:

```
KRCC (lang=ko-KR)                  ENCC (lang=en-US)
1  00:00:01,000 --> 00:00:03,000   1  00:00:01,000 --> 00:00:04,000
   첫 번째 자막입니다. / 두 번째 줄        First subtitle line. / second line
2  00:00:04,000 --> 00:00:06,000   2  00:00:04,000 --> 00:00:08,000
   똠방각하 - 확장 한글 ... 테스트          UHC-only hangul test
```

0초 큐가 사라졌다(1~3초, 4~6초). 이 두 트랙을 libmpv 에 주입한 결과(`probe3.py`):

```
자막 트랙: id=1 title='Korean'  lang=kor selected=True
           id=2 title='English' lang=eng selected=False
표시:  1.00s  첫 번째 자막입니다. / 두 번째 줄
       4.00s  똠방각하 - 확장 한글(UHC 전용 글자) 테스트
```

**P3(겹침)·P4(0초) 가 모두 사라졌고, 한국어가 기본 트랙으로 선택됐다.**
`sub_add(파일, 'select', 제목, 언어코드)` 로 트랙 제목·언어를 지정할 수 있어 UI 트랙 메뉴에 그대로 쓸 수 있다.

## 4. 설계에 주는 결론

1. **인코딩은 파일을 다시 쓰지 않는다.** 우리가 판정한 결과를 `--sub-codepage=+<enc>` 로 주입한다.
2. **파일 생성은 한·영 통합 SAMI 에만 필요하다.** 단일 언어 SAMI·SRT 는 ①만 하면 끝.
3. `--sub-stretch-durations` 는 **폴백**으로만 쓴다(클래스 분리가 실패했을 때). 켜면 한·영이 겹치므로 기본값으로 삼지 않는다.
4. 일본어·중국어 자막을 CP949 로 오판하지 않으려면 **uchardet 의 CJK 판정을 한글 비율보다 우선**해야 한다.

## 5. 아직 검증하지 않은 것

- 실제 방송·영화 자막 표본(수십 개)에 대한 판정 정확도. 지금 표본은 **합성 11개**뿐이다.
- 임계값 0.7 의 타당성 — 한자가 많이 섞인 한글 자막을 넣어 보지 않았다.
- `&nbsp;` 외의 종료 관례(빈 `<P>`, 공백 문자열)와 클래스 없는 SAMI 의 처리.
- SAMI 의 `<STYLE>` 에 `lang:` 이 없고 클래스 이름도 관례를 벗어난 경우.
