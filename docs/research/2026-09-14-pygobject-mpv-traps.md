# 실측 기록 6 — PyGObject·python-mpv 의 조용한 함정 (2026-09-14)

v0.2 를 만들며 만난 **조용히 잘못 동작하는** API 세 가지. 셋 다 예외를 던지지 않고
그럴듯하게 틀린 값을 돌려주기 때문에, 테스트가 없으면 한참 뒤에야 드러난다.

## 1. `python-mpv` 의 절대 seek 가 되감긴다 ⚠ 가장 위험

```python
mpv.seek(9.0, reference="absolute")     # 9초로 가지 않는다
```

같은 영상에서 네 방식을 나란히 재 봤다(창이 떠 있고 렌더는 초당 25회 도는 상태):

| 호출 | 결과 |
|---|---|
| `mpv.seek(9, reference='absolute')` | **0.80초** ❌ 되감긴다 |
| `command('seek', 9, 'absolute')` | 9.92초 ✅ |
| `time_pos = 9.0` | 9.92초 ✅ |
| `command('seek', '9', 'absolute+exact')` | 9.88초 ✅ |

mpv 로그에는 `execute seek (to 9.000000)` 이 찍힌다 — **요청은 갔는데 결과가 0 근처다.**
python-mpv 1.0.8 의 래퍼가 `precision` 인자까지 함께 보내면서 mpv 가 오해하는 것으로 보인다.

**처방**: 명령을 직접 보낸다. 자막 싱크를 맞추는 도구이므로 키프레임이 아니라 정확한 지점으로 가야 한다.

```python
self._mpv.command("seek", float(seconds), "absolute+exact")
```

**왜 늦게 발견됐나** — 기존 검증이 전부 우연히 통과했다.
- 탐색 검증은 **상대** seek 라 정상 동작했다(`reference` 기본값이 relative).
- 정지 검증은 `seek(0, absolute)` 인데, 절대 seek 가 **어차피 0 근처로 가니** 맞아떨어졌다.

절대 seek 가 처음으로 진짜 쓰인 곳이 자막 에디터(특정 시각의 큐 잡기)였고, 거기서 드러났다.

## 2. `Gdk.Rectangle(x=..., y=...)` 이 무시된다

```python
popover.set_pointing_to(Gdk.Rectangle(x=321, y=234, width=1, height=1))   # (0,0) 이 들어간다
```

boxed 구조체라 PyGObject 가 생성자 키워드를 필드에 넣어 주지 않는다. 예외도 없다.
우클릭 메뉴가 클릭한 자리가 아니라 **좌상단**에 뜨던 원인이었다(전체화면에서는 화면 밖이라 안 보였다).

**처방**: 만든 뒤 필드에 직접 대입한다.

```python
rect = Gdk.Rectangle()
rect.x, rect.y, rect.width, rect.height = int(x), int(y), 1, 1
```

## 3. `vo='libmpv'` 는 렌더 컨텍스트가 없으면 멈춘다

창 없이 `Player` 를 만들어 재생하면 `duration` 조차 오지 않는다(타임아웃).
렌더 컨텍스트(GLArea)가 붙어야 디코딩이 진행되기 때문이다.

**처방**: `Player(vo="null")` 로 로직만 시험할 수 있게 인자를 열어 뒀다.
단 스크린샷처럼 **렌더 결과가 필요한 기능은 vo=null 로 검증되지 않는다** — GUI 시나리오에서 봐야 한다.

## 4. `get_text(..., include_hidden_chars=False)` 가 감춘 글자를 지운다 ⚠ 파일이 손상된다

마크다운 라이브 프리뷰를 만들며 `#`, `**` 같은 마크업에 `invisible` 태그를 붙였다.
그러자 **저장된 파일에서 그 문자들이 사라졌다.**

```
저장 결과: 'lecture\n\n[00:00:45] 합의 알고리즘 정리\n'   <- '#' 와 '##' 가 없다
기대:      '# lecture\n\n## [00:00:45] 합의 알고리즘 정리\n'
```

원인은 한 글자였다:

```python
self._buffer.get_text(start, end, False)   # False = include_hidden_chars
```

세 번째 인자가 `False` 면 **invisible 태그가 붙은 문자를 빼고** 돌려준다. 화면을 꾸미려고 단
태그가 저장 경로로 새어 들어가 원본을 갉아먹었다. 예외도 경고도 없다.

**처방**: 저장에 쓰는 읽기는 반드시 `True`. 보이는 것만 바뀌어야 하고 파일 내용은 손대지 않는다.

**왜 단위 테스트가 못 잡았나** — 테스트가 버퍼를 직접 `get_text(start, end, True)` 로 읽어
확인했다. 정작 저장은 `_text()` 라는 다른 경로를 탔고 거기가 `False` 였다.
**테스트는 실제로 쓰이는 길을 지나야 한다.** 지금은 `_text()` 를 검증한다.

## 5. 덧 — 이번에도 계측이 먼저 틀렸다

`set_start()` 의 최소 길이 보장을 `end <= start` 로 판단했더니 **1밀리초짜리 큐**가 남았다.
'겹쳤는가'가 아니라 '충분히 긴가'로 봐야 했다. 테스트가 잡았다.

`srt_to_ms('1:30')` 이 30초로 읽히던 것도 같은 종류다 — 옵션 그룹 두 개짜리 정규식은
탐욕 매칭 탓에 `1` 을 시간으로 가져간다. 콜론으로 잘라 **뒤에서부터** 초·분·시로 채워야 한다.

## 교훈

셋 다 **예외 없이 그럴듯하게 틀린 값**을 돌려준다. 그래서 눈으로 보이는 증상(메뉴가 엉뚱한 데
뜬다, 자막이 안 잡힌다)이 나타날 때까지 몰랐다. 값을 쓰는 쪽에서 **기대값을 단언하는 테스트**가
유일한 방어다 — 실제로 셋 다 그렇게 잡혔다.
