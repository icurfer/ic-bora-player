# OS 공통 UI·UX 관리 검토

2026-10-10 · 기준 소스 `d85868b` · 검토 완료, 아래 개선안은 미구현.

## 결론

GTK4/libadwaita 화면 한 벌을 유지하는 현재 구조가 적합하다. Windows용 화면을
새로 만들 필요는 없다. 통합 대상은 배치·행동·상태·스타일 기준이며, OS가 맡는
창 장식·글꼴 렌더링까지 픽셀 단위로 같게 만드는 것이 목표는 아니다.

`app.py`가 공통 `BoraWindow`를 사용하고, `window.py`, `notes/panel.py`,
`ai/panel.py`가 양쪽 OS의 동일한 화면이다. Windows의 `application.py`는
Python/GIO 명령줄 보정이며 별도 화면이 아니다. GTK 자체도 Windows 백엔드를 제공한다.

## 공통 관리와 플랫폼 경계

| 공통으로 유지할 것 | OS 어댑터로 유지할 것 |
|---|---|
| 영상·메모 위/대화 아래 배치, 도구 위치, 설정 구성 | 창 시스템·GL 컨텍스트·GIO 연동 |
| 작업 이름, 아이콘 의미, 툴팁, 단축키와 포커스 처리 | 터미널 실행, 경로, DLL·외부 실행 파일 탐색 |
| 저장/외부 수정 충돌, 전송 중/취소/오류 상태 | OS 파일 선택기와 키 저장소 구현 |
| 색상 역할, 여백, 최소 크기 기준, 접근성 | OS 글꼴 대체와 IME·배율의 실제 동작 검증 |

지원하지 않는 기능은 화면에서 조용히 없애 배치를 달리하기보다 사용 불가 이유를
같은 위치에서 설명하는 방향을 권고한다. 기존 `platform/` 경계를 유지한다.

## 현재 소스에서 확인한 흔들림 요인

| 위치 | 확인한 내용 | 개선 방향 |
|---|---|---|
| `notes/panel.py::_make_tags` | 링크·인용·코드 배경 색을 직접 지정 | 공통 의미별 색상으로 관리하고 밝은/어두운/고대비 검증 |
| `window.py`의 삭제 구간 안내 | Cairo `sans`, 크기 15로 한국어 직접 출력 | Pango 기반 공통 텍스트 처리 검토 |
| `clip/timeline.py` | 직접 그리는 색상·글자 크기 다수 | 타임라인용 공통 스타일 역할로 모으기 |
| 학습 패널 | 요청 폭 340, 개별 패널 320 및 도구막대 | 배율·한국어 글꼴별 최소 폭과 잘림 실측 |
| 도구 아이콘 | 시스템 아이콘 테마 이름에 의존 | 배포 런타임의 필수 아이콘 존재 검사와 리소스 포함 |
| `glarea.py` | scale factor를 렌더 크기에 적용 | 소수 배율·모니터 이동에서 별도 실측 |

영상 위 검은 안내 배경처럼 용도상 필요한 고정 대비는 유지할 수 있다. 모든 색상을
무조건 시스템 색으로 바꾸는 작업은 권고하지 않는다. 일반 위젯의 기존 Adwaita
스타일은 활용하되 직접 그리는 부분도 테마 변경에 맞게 검토한다.

## 권고하는 구현 순서

1. 공통 UI 기준 문서와 수용 시나리오를 하나로 둔다. 메모 위·대화 아래, 환경설정
   톱니와 툴팁, Ctrl+Enter 전송, Ctrl+W 종료, 입력 중 재생 단축키 차단을 명시한다.
2. 공통 스타일·액션 정의를 단계적으로 모은다. 예를 들어 `src/bora/ui/` 아래에
   색상 역할·텍스트 처리·공통 액션을 둘 수 있다. 현재 패널을 모두 한 파일로 합칠
   필요는 없다. 실제 파일·함수 범위는 구현 기획 때 확정한다.
3. 시스템/밝게/어둡게 선택과 아이콘 리소스 관리를 검토한다. OS 테마를 강제로
   덮어쓰지 않고 한국어 글꼴 대체와 접근성 설정을 존중한다.
4. 검증한 GTK/libadwaita/PyGObject/libmpv·아이콘 런타임 조합을 OS별로 기록한다.
   Windows 최신 런타임 성공과 프로젝트의 libadwaita 1.1 API 제한 준수는 별도다.
   최신 공식 문서의 API·CSS 문법은 도입 가능 버전을 확인한 뒤 사용한다.
5. 공통 시나리오를 각 OS의 실제 실행에 적용한다. Linux XTest 입력 방식을 Windows에
   그대로 쓰지 않고 OS별 입력 드라이버 아래 동일한 기대 결과를 검사한다.

프레임워크 전체 교체는 현재 근거로 필요하지 않다. 재생 임베딩·자막·메모·IME를
다시 검증하는 비용이 생긴다. 현재 GTK 공통 화면의 스타일과 검증 빈틈부터 줄인다.

## 검증 기준과 현재 한계

- Ubuntu 26.04와 기록된 Windows 25H2 환경에서 같은 영상·한국어 경로·메모로 비교한다.
- 기본/최소 창, 밝은/어두운/고대비, 배율 100/125/150/200%를 위험에 맞게 조합한다.
  전체 조합을 매 커밋마다 요구하지는 않는다. Windows 모니터 간 배율 전환도 포함한다.
- 메모 편집과 AI 대화를 동시에 볼 수 있는지, 도구가 잘리지 않는지, 탭 순서·포커스·
  실제 한국어 조합 입력·Ctrl+Enter·Ctrl+W·충돌 시 저장 보호를 확인한다.
- 스크린샷은 OS별 기준 이미지를 두고 글꼴 안티앨리어싱 차이를 허용한다.
  배치·상태·행동 일치와 화면 잘림을 먼저 판정한다.

이번 검토는 소스와 기존 검증 기록, 공식 문서 및 독립 UI 검토에 근거한다.
현재 세션에서 Windows를 다시 실행하거나 양쪽 화면을 새로 비교하지 않았다.
Windows 완료 기록에는 재생·자막·메모·클립 성공이 있지만 메모 입력은 GtkTextBuffer
API 검사이므로 실제 IME/키입력 E2E와 다르다. portable 배포·Win10·Linux GUI 회귀도
남아 있다. 따라서 전체 Windows 지원이나 OS별 시각적 일치가 검증됐다고 하지 않는다.
