# 영상별 학습 에이전트와 학습메모

기준: 공통 UI 기획(shared-ui.md)의 메모/대화 동시 배치를 독립 표시로 확장한다.
포탈 task 361. 사용자 확정: 영상에 연결하되 메모만 분리, 원문과 AI 요약 모두 제공.

## 학습 흐름
사용자는 시청 중 떠오른 생각을 빠르게 맡겨 두고 학습을 이어가려 한다. 메모와 에이전트를
동시에 쓰되 답변을 기다리도록 강요하지 않는다. 나중에 시각과 장면으로 생각의 맥락을 복원한다.

## 배치 위치
메인 창에 메모/학습 에이전트 독립 토글을 두고 둘 다 열면 기존 세로 분할을 유지한다.
에이전트에 현재 영상 캡처 첨부와 대화→학습메모(원문/AI 요약) 동작을 둔다.

## 설정·비밀값 보관 위치
영상별 기존 conversations JSON을 유지한다. 캡처는 영상 옆 메모 assets에 고유 이름으로
저장한다. 학습메모는 기존 영상 옆 md에 사용자 확인 후 추가한다. 새 자격 저장은 없다.

## 따르는 기존 패턴
GTK4/libadwaita 1.1, 기존 Codex/OpenAI runner와 이미지 검증, NoteDocument 저장 충돌 보호를
사용한다. 화면을 OS별 복제하지 않고 Linux에서 먼저 검증한다.

## 동작
- 메모만/에이전트만/둘 다/둘 다 닫힘 네 상태. 패널 숨김은 대화 삭제·취소가 아니다.
- 현재 답변의 질문과 답변을 함께 메모에 넣는다. 과거 질문 없는 답변은 누락을 표시한다.
- 전체 원문은 Q&A 마크다운으로 미리보기하고, 요약은 선택한 AI로 별도 요청해 미리보기한다.
  검토 후 메모 끝에 추가한다. 요약 중 취소·닫기·영상 전환은 늦은 결과를 차단한다.
- 대화 원문은 요약으로 대체하지 않는다. 길이 제한 초과 시 조용히 잘라 요약하지 않는다.
- 현재 영상 프레임을 메모 작성 없이 캡처 첨부한다. 전송 전 썸네일·제거, 질문/영상별 분리,
  기존 이미지 개수/용량 제한과 실제 바이트 전송을 유지한다. 캡처는 사용자 데스크톱이 아니다.
- 파일 전환·저장 충돌·요약 오류에서 메모와 대화 원본을 보존한다.
- P는 시각 핀과 현재 영상 화면을 메모에 함께 남기고 제목 위치에 입력하게 한다.
  Shift+P는 입력 포커스를 옮기지 않고 기록한다. 구간 핀의 화면에는 실제 캡처 시각을 표시한다.
  캡처 실패에도 시각 핀은 보존하고 실패를 알린다. 기존 핀 파일 형식은 유지한다.
- 요약 창은 메모 편집을 막지 않는다. 기본적으로 창을 열 때의 메모와 대화를 함께 요약하며
  메모 포함은 해제할 수 있다. 원문 내보내기는 대화만 추가해 메모 전체의 중복 삽입을 피한다.
- 우클릭 메뉴와 환경설정의 재생 속도 항목에 `,` 느리게 / `.` 빠르게를 표시한다.

## 검증
Q&A 매칭, 전체 대화 변환, 요약 취소/오류/지연, 캡처 실제 PNG 첨부/제거/영상 분리,
실제 GTK 배치와 단축키, 재시작 대화 유지, 메모 저장 실패를 검증한다. AI 응답은 모의와
실제 호출을 구분한다. Windows 실측과 설치는 후속이다.
