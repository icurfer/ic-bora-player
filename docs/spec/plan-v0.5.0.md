# plan-v0.5.0 — 하단 타임라인에서 컷 편집

`plan-v0.4.0.md`("보면서 잘라낸다")의 **정정**. v0.4 는 구간을 목록에 적는 것까지만 만들었고,
그것으로는 컷 편집이 되지 않는다.

## §0 v0.4 가 틀린 곳 ⚠ 이 절이 이 기획의 출발점

기획서 v0.4 §0-1 에 이렇게 적었다:

> **타임라인 편집기를 만들지 않는다.** … 그건 Kdenlive 의 일이고, 그걸 이기려 들면 이 프로젝트가 죽는다.

**이 선이 잘못 그어졌다.** 사용자가 원한 것은 Kdenlive 가 아니라 **프리미어·캡컷의 하단 편집 영역**,
즉 "영상을 보면서 그 자리에서 자르고 붙이는 띠"였다. 목록으로는 다음이 전부 안 된다.

| v0.4 로 안 되는 것 | 왜 |
|---|---|
| 전체 중 어디를 담았는지 본다 | `03:20 ~ 03:50` 이라는 글자뿐. 공간 감각이 없다 |
| 담은 뒤 경계를 다듬는다 | "앞을 2초 당기자"가 없다. 재생 위치로 가서 `F5`/`F6` 를 다시 |
| 이어붙인 결과를 미리 본다 | 내보내기 전까지 모른다 |
| 필요 없는 데를 들어낸다 | 담기(keep)만 있고 잘라내기(cut)가 없다 |

선을 다시 긋는다: **트랙·전환·합성은 여전히 안 한다.** 하지만 **한 영상을 자르고 순서를 바꾸고
이어 붙이는 것**은 이 앱의 일이다. 강의를 보며 복습본을 만드는 데 그게 필요하기 때문이다.

## §1 실측이 정한 것 (2026-09-19)

| 실측 | 설계 결론 |
|---|---|
| 필름스트립 100장을 `fps` 필터로 전체 훑기 — **291.8초** | 미리 다 뽑으면 타임라인 열 때 5분을 기다린다. **못 쓴다** |
| 개별 seek 로 10장 — **2.64초** (장당 0.26초) | 100장이면 약 26초. 11배 빠르다 |
| 썸네일 1장(높이 60px) — **3.2 KB** | 수백 장을 메모리에 들고 있어도 부담 없다 |

→ **보이는 구간만, 게으르게, 백그라운드로** 뽑는다. 타임라인은 즉시 열리고 그림은 채워진다.
확대하면 그 구간을 다시 뽑는다. 뽑은 것은 캐시한다.

## §3 조작 — 여기가 v0.4 와 갈리는 지점

| 조작 | 방법 |
|---|---|
| **자르기** | 재생헤드 자리에서 `S` 또는 ✂ — 그 지점에서 구간이 둘로 쪼개진다 |
| **구간 선택** | 클릭 |
| **경계 다듬기** | 구간의 **양 끝을 잡고 끈다**. 끌면서 그 프레임이 영상에 뜬다 |
| **삭제** | 선택하고 `Delete` — 결과에서 빠진다(원본은 그대로) |
| **되살리기** | 삭제된 구간은 회색으로 남는다. 다시 누르면 살아난다 |
| **순서 바꾸기** | 구간을 잡아 옆으로 끈다 |
| **재생헤드 이동** | 타임라인 아무 데나 클릭 |
| **미리보기** | 남은 구간만 이어서 재생한다 (내보내기 전에 결과를 본다) |
| **되돌리기** | `Ctrl+Z` / `Ctrl+Shift+Z` |

**기본 상태가 v0.4 와 반대다.** 처음엔 영상 전체가 구간 하나로 놓여 있고, 자르고 **지워서**
남길 것을 만든다. 담기(keep)가 아니라 잘라내기(cut)가 기본이다 — 강의에서 잡담을 걷어내는
쪽이 훨씬 흔하기 때문이다. 필요한 데만 담고 싶으면 전체를 지우고 원하는 구간만 되살리면 된다.

## §4 설계

### 4-1. 배치 위치

`src/bora/clip/` 을 이어 쓴다. v0.4 의 `runner.py`·`probe.py` 는 그대로 쓸 수 있다 —
**내보내기 경로는 바뀌지 않는다.** 바뀌는 것은 "구간을 어떻게 정하느냐"뿐이다.

| 파일 | 상태 | 역할 |
|---|---|---|
| `model.py` | **확장** | `Clip` 에 `enabled` 추가, `Timeline`(자르기·삭제·순서·되돌리기) 신설 |
| `timeline.py` | **신규** | `Gtk.DrawingArea` — 그리기와 마우스 조작 |
| `thumbs.py` | **신규** | 썸네일을 게으르게 뽑아 캐시한다 |
| `runner.py` | 그대로 | 내보내기는 `enabled` 인 구간만 받으면 된다 |
| `probe.py` | 그대로 | 코덱 대조 방어선 |
| `dialog.py` | **축소** | 목록 창은 남기되, 편집의 중심은 타임라인으로 옮긴다 |

### 4-2. 설정·비밀값 보관 위치

비밀값 없음. 썸네일 캐시는 `~/.cache/bora/thumbs/<파일해시>/` 에 두고 **지워도 되게** 만든다.
편집 상태(자른 자리·삭제 여부)는 v0.4 와 같이 저장하지 않는다 — 한 번 보는 동안의 작업물이다.
> 다만 이번에는 작업이 길어질 수 있어, **닫을 때 편집 중이면 묻는다**.

### 4-3. 따르는 기존 패턴

- **게으른 로딩 + 백그라운드** — `stt/runner.py` 처럼 스레드에서 뽑고 `GLib.idle_add` 로 올린다
- **libadwaita 1.1 범위** — `Gtk.DrawingArea` 는 GTK 4.0 부터라 22.04 에서도 된다
- **되돌리기는 상태 스냅숏** — 구간 목록이 작아서(수십 개) 통째로 복사해 쌓으면 충분하다.
  연산별 역연산을 만드는 것보다 틀릴 여지가 적다

### 4-4. 미리보기를 어떻게 하나

남은 구간만 이어서 재생해야 하는데, **내보내기 없이** 해야 한다.
mpv 의 `ab-loop` 는 구간 하나뿐이라 부족하다 → 재생 중 `time-pos` 를 지켜보다가 구간 끝에
닿으면 다음 구간 시작으로 `seek` 한다. 경계에서 순간 끊김이 있지만 **결과 확인용으로는 충분**하다.
(실제 내보낸 파일은 끊기지 않는다 — 실측 D 에서 확인했다.)

## §5 성공 기준

| | 수용 테스트 |
|---|---|
| T1 | 타임라인을 열면 **1초 안에** 뜨고, 썸네일이 뒤이어 채워진다 |
| T2 | 재생헤드 자리에서 자르면 구간이 둘로 쪼개진다 |
| T3 | 구간 끝을 끌면 경계가 바뀌고 그 프레임이 영상에 뜬다 |
| T4 | 삭제한 구간이 결과에서 빠지고, 되살리면 돌아온다 |
| T5 | `Ctrl+Z` 로 자르기·삭제·이동이 되돌아간다 |
| T6 | 미리보기가 남은 구간만 이어서 재생한다 |
| T7 | 내보낸 파일이 미리보기와 같은 내용이고 재생된다 |
| T8 | 1시간 영상에서 확대·이동이 버벅이지 않는다 (60fps 유지) |

## §6 위험

| 위험 | 대응 |
|---|---|
| DrawingArea 직접 그리기가 느리다 | 썸네일은 미리 축소해 두고, 보이는 범위만 그린다. T8 이 지킨다 |
| 드래그 조작이 미끄럽지 않으면 안 쓰게 된다 | 끄는 동안 영상이 따라 움직여야 한다(T3). 이게 되면 감이 잡힌다 |
| 편집 중 실수로 닫아 작업을 잃는다 | 닫을 때 묻는다 (§4-2) |
| 기능이 커져 플레이어가 무거워진다 | 타임라인은 **접힌 상태가 기본**. 안 펴면 없는 것과 같다 |
