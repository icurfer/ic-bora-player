# OS 공통 UI 관리

기준: [공통 UI 검토](../research/2026-10-10-shared-ui-ux.md)의 권고를 Linux 우선 구현 범위로 구체화한다.

## 배치 위치
기존 GTK 화면을 유지하고 `src/bora/ui.py`에 공통 크기·메모 색상 역할·영상 안내 스타일을 둔다.
메모 위/AI 대화 아래 배치와 버튼·단축키 위치를 모든 OS에서 동일하게 유지한다.

## 설정·비밀값 보관 위치
새 설정·비밀값은 없다. 시스템 테마를 따르며 기존 설정과 메모 형식을 유지한다.

## 따르는 기존 패턴
Adwaita 의미 스타일과 시스템 글꼴, GTK4/libadwaita 1.1 API 범위를 유지한다.
OS 분기는 기존 platform/만 사용한다. 최신 테마 API나 새 의존성을 도입하지 않는다.

## Linux 우선 변경
메모의 링크/목록/인용/코드 색상을 시스템 테마 역할로 해결하고, 테마 전환 시 기존
텍스트 태그만 갱신한다. 텍스트·커서·선택·저장 상태·질문 초안은 바꾸지 않는다.
기본 창과 학습 패널 크기는 공통 정의를 참조한다. 삭제 구간 한국어 안내는
Cairo 기본 글꼴 대신 GTK의 Pango 레이아웃으로 그려 시스템 글꼴·크기를 반영한다.
영상 안내는 검은 배경 대비를 유지한다. 타임라인 색상 전면 변경은 이번 범위 밖이다.

## UI 계약
- 영상과 메모/대화 동시 표시, 메모 위·대화 아래 분할 크기 조절을 유지한다.
- 환경설정 톱니/툴팁, 입력 중 Space/방향키 보호, Ctrl+Enter 전송과 Ctrl+W 종료를 유지한다.
- 응답을 메모로 옮기는 동작은 명시적이며 전송·오류·취소로 초안을 잃지 않는다.
- 밝은/어두운 화면에서 글과 링크를 읽을 수 있고 링크는 밑줄로도 식별한다.
- OS 창 장식과 글꼴 모양 차이는 허용한다. 기능 위치와 상태·행동을 다르게 만들지 않는다.

## 수용 검사
격리 Linux GTK 실행에서 밝게/어둡게 전환, 메모/선택/초안 보존, 기본/최소 창의
도구 접근, 필요한 아이콘, 한국어 안내 캡처를 확인한다. 기존 실제 키입력 시나리오와
재생 시나리오를 재실행한다. 단위·모의 응답 검사는 실제 IME/API 검증과 구분한다.
Windows는 동일 소스와 시나리오로 후속 실측하며 Linux 성공을 Windows 통과로 쓰지 않는다.

## API 참고
[Adw StyleManager](https://gnome.pages.gitlab.gnome.org/libadwaita/doc/1-latest/class.StyleManager.html)의
dark/high-contrast 상태를 사용한다. 1.6+ accent API와 1.7+ 글꼴 API는 쓰지 않는다.
[GTK named color 조회](https://docs.gtk.org/gtk4/method.StyleContext.lookup_color.html)는
4.10 이후 deprecated지만 GTK4 초기 버전 호환을 위해 공통 모듈 내부에서만 사용한다.
