# plan-v0.2.0 — 보면서 고치는 플레이어

작성: 2026-09-14 · 상태: **기획 · 구현 대기**
이전: [`plan-v0.1.0.md`](plan-v0.1.0.md) (v0.1 은 26.04 에서 T1~T4 통과, `version` 0.5.0)
요구 출처: [`../requirements/backlog.md`](../requirements/backlog.md) #9~#14

## §0 한 줄 정의

**v0.1 이 "자막이 그냥 나오게" 했다면, v0.2 는 "안 맞는 자막을 보면서 고치게" 한다.**
나머지(이어보기·재생 속도·최근 파일·스크린샷·자막 글꼴)는 플레이어로서 당연히 있어야 할 것들을 채운다.

## §1 왜 자막 에디터인가 — 조사 결과 (2026-09-14)

국내 자막은 싱크가 어긋난 경우가 흔한데, **고칠 자리가 없다.**

| 도구 | 재생 중 큐 타이밍 찍기 | 저장 | 감상용 플레이어인가 |
|---|---|---|---|
| **Aegisub** | ✅ `Ctrl+3` 시작 / `Ctrl+4` 종료를 현재 프레임으로 | ✅ | ❌ 편집 전문 도구(오디오 파형 중심) |
| **Subtitle Edit** | ✅ | ✅ | ❌ 편집기 |
| 팟플레이어 | ❌ — 2017년에 "현재 위치 이후 싱크 조절"만 추가 | ❌ | ✅ |
| VLC · mpv · Celluloid · Haruna | ❌ 전체 오프셋만 | ❌ | ✅ |

**편집기는 감상용이 아니고, 플레이어는 저장을 못 한다.** 그 사이가 비어 있다.
Aegisub 의 "현재 프레임을 시작/끝으로 박는다"는 발상은 그대로 가져오되,
**감상하다가 거슬리는 줄 하나를 그 자리에서 고치는 흐름**으로 만든다.

> 근거: Aegisub 공식 문서(timing), Aegisub 3.0 변경 기록, 팟플레이어 변경 기록(1.7.4353).

## §2 자막 에디터 — 무엇을 만드나

### 2-1. 핵심 흐름 (사용자 제안 그대로)

```
재생 중 자막이 늦다 → [Space] 일시정지 → [E] 에디터 열기
  → 지금 화면에 뜬 큐가 이미 선택돼 있다
  → [현재 시각을 시작으로] 버튼 (또는 단축키)  → 그 큐의 시작 시각이 지금 위치로 바뀐다
  → 값을 직접 타이핑해 미세 조정해도 된다
  → [저장]  → 원본 옆에 쓴다(백업 후) 또는 다른 이름으로
```

**핵심은 "지금 화면의 큐"를 찾아 주는 것**이다. 사용자가 목록에서 줄을 뒤지게 하면 감상 흐름이 끊긴다.

### 2-2. 편집 단위

| 기능 | 설명 |
|---|---|
| 현재 큐 잡기 | 재생 위치에 걸린 큐를 자동 선택. 없으면 **직전 큐**를 고른다(자막이 늦게 뜨는 경우가 흔하다) |
| 시작/끝을 현재 시각으로 | 일시정지한 위치를 그 큐의 시작 또는 끝으로 박는다 |
| 시각 직접 입력 | `00:12:34,567` 형식. 잘못된 값은 거부하고 이유를 보여준다 |
| 본문 수정 | 오타·줄바꿈 고치기 |
| 이 줄부터 뒤로 전부 밀기 | 중간부터 어긋나는 자막에 쓴다. **국내 자막에서 가장 흔한 형태** |
| 전체 밀기 | 지금의 `sub-delay` 를 파일에 굳힌다 |
| 큐 추가·삭제 | 최소 기능만 |
| 되돌리기 | 최소 1단계. 편집 중 원본은 건드리지 않는다 |

### 2-3. 저장 정책 — 원본을 함부로 덮지 않는다

1. 저장 시 **원본을 `<이름>.bak` 으로 복사**한 뒤 덮어쓴다(같은 이름이 있으면 번호를 붙인다).
2. `.smi`(SAMI) 원본은 **SRT 로 저장**한다 — v0.1 의 분리기가 이미 SRT 를 만든다.
   원본 SAMI 를 그대로 다시 쓰는 것은 범위 밖(형식 왕복 손실).
3. 읽기 전용 위치면 저장 위치를 물어본다.
4. 저장 후 **그 파일로 자막을 다시 로드**해 방금 고친 결과가 화면에 바로 반영되게 한다.

### 2-4. 하지 않는 것

- 오디오 파형 표시 (Aegisub 의 영역이다. 여기서 하면 감상용 플레이어가 아니게 된다)
- ASS 스타일 편집·타이포세팅·카라오케
- 번역 기능, 자동 자막 생성(Whisper 등)
- 여러 자막 파일 동시 편집

## §3 나머지 기능

| # | 기능 | 설계 요점 |
|---|---|---|
| 9 | **이어보기** | 파일 경로 해시 + 마지막 위치를 사용자 설정 폴더에 기록. 다음에 열면 "이어 볼까요" 를 토스트로 묻고 몇 초 안에 답이 없으면 처음부터. **끝까지 본 파일은 기록하지 않는다**(95% 이상이면 완료로 본다) |
| 10 | **재생 속도** | 0.25x~4x, `[`/`]` 는 이미 자막 싱크에 쓰므로 다른 키를 쓴다. mpv `speed`. 음정 유지(`audio-pitch-correction`)는 기본 켬 |
| 10 | **화면 비율·확대** | mpv `video-aspect-override`, `video-zoom`, `panscan`. 원본/16:9/4:3/화면맞춤 |
| 11 | **최근 파일** | 경로·마지막 위치·자막 선택을 함께 기록. 최대 20개. 없어진 파일은 목록에서 지운다 |
| 12 | **스크린샷** | mpv `screenshot-to-file`. 자막 포함/제외 선택. 저장 위치는 XDG 그림 폴더 기본 |
| 13 | **자막 글꼴·크기** | mpv `sub-font`, `sub-font-size`, `sub-color`, `sub-border-size`. 국내 자막은 글자가 작아 안 보이는 일이 잦다 |

**설정이 생긴다** — v0.1 은 설정이 없었다. 이어보기·최근 파일·자막 글꼴은 모두 저장이 필요하다.
→ `~/.config/bora/state.json` 하나로 관리한다(§4).

## §4 아키텍처 추가분

```
src/bora/
  state.py            설정·이어보기·최근 파일 (JSON 하나, 원자적 쓰기)
  subtitle/
    model.py          편집 가능한 자막 모델 (큐 목록 + 되돌리기)
    writer.py         SRT 저장 (+ 백업)
  editor/
    window.py         에디터 창 (플레이어와 분리된 창, 같은 프로세스)
    bindings.py       "현재 시각 박기" 같은 플레이어 연동
```

**에디터를 별도 창으로 둔다.** 영상 위에 올리면 좁고, 전체화면에서 쓰기 어렵다.
플레이어와 같은 프로세스라 재생 위치를 바로 읽고 쓸 수 있다.

## §5 성공 기준 (수용 테스트)

| # | 시나리오 | 기대 |
|---|---|---|
| E1 | 자막이 2초 늦은 파일을 열고, 늦게 뜬 시점에 일시정지 → 에디터 → "시작을 현재 시각으로" | 그 큐의 시작이 현재 위치로 바뀌고 화면에 바로 반영된다 |
| E2 | "이 줄부터 뒤로 전부 밀기" 로 -2초 | 그 줄 이후 큐가 전부 2초 당겨지고, 앞 줄은 그대로다 |
| E3 | 저장 | `<이름>.bak` 이 생기고 원본이 갱신된다. 다시 로드돼 화면에 반영된다 |
| E4 | SAMI(.smi) 를 열어 편집 후 저장 | `.srt` 로 저장되고 원본 `.smi` 는 그대로 남는다 |
| R1 | 영화를 10분 보다 닫고 다시 열기 | "이어 볼까요" 가 뜨고, 수락하면 그 지점부터 |
| R2 | 끝까지 본 파일을 다시 열기 | 이어보기를 묻지 않는다 |
| S1 | 재생 속도 1.5x | 소리 음정이 유지된다 |
| S2 | 스크린샷 | 자막 포함/제외 두 장이 그림 폴더에 저장된다 |
| S3 | 자막 크기 키우기 | 즉시 반영되고, 다음에 열 때도 유지된다 |

## §6 위험

| 위험 | 완화 |
|---|---|
| **원본 자막을 망가뜨린다** | 저장 전 `.bak` 필수. 편집 중에는 메모리에서만 다룬다. E3 을 회귀 테스트로 고정 |
| 에디터가 커져 "감상용 플레이어"가 아니게 된다 | §2-4 의 '하지 않는 것'을 지킨다. 파형·스타일 편집은 넣지 않는다 |
| 설정 파일이 깨져 앱이 안 뜬다 | 읽기 실패 시 기본값으로 시작하고 백업해 둔다. 원자적 쓰기(임시 파일 + rename) |
| 이어보기가 사생활 기록이 된다 | 최근 파일·이어보기를 끄는 설정을 둔다. 목록 비우기 제공 |
| 기능이 한꺼번에 늘어 회귀가 는다 | §7 순서대로 나눠 넣고 단계마다 검증 시나리오를 추가한다 |

## §7 순서

작은 것부터 넣어 매 단계 동작하는 상태를 유지한다.

1. `state.py` — 설정 저장 기반 (이어보기·최근 파일·자막 글꼴이 모두 여기 의존)
2. 재생 속도 · 화면 비율 · 확대 · 스크린샷 (mpv 속성만 건드리면 되는 것들)
3. 자막 글꼴·크기
4. 이어보기 · 최근 파일
5. **자막 모델 + SRT 저장기** (테스트로 고정)
6. **에디터 창** — 현재 큐 잡기, 시각 박기, 뒤로 밀기, 저장
7. 수용 테스트 E1~E4 · R1~R2 · S1~S3

## §8 확인할 것

| # | 확인 | 왜 |
|---|---|---|
| 8-1 | mpv `sub-delay` 와 편집한 파일의 관계 | ✅ **확정**: delay 는 파일 시각에 **얹히는 별도 오프셋**이다(실측). 둘이 남아 있으면 두 번 밀린다 → **저장할 때 현재 delay 를 파일에 굳히고 delay 를 0 으로 되돌린다** |
| 8-2 | 편집 중 자막을 다시 로드하는 가장 싼 방법 | ✅ **확정**: `sub-reload` 는 약 0.5초 걸리지만 **재생은 끊기지 않는다**(위치 1.04 → 1.52 로 계속 진행). 매 편집마다 부르지 말고 **저장 시점에만** 부른다 |
| 8-3 | SAMI 원본의 큐를 SRT 로 옮길 때 클래스 정보 | ⏳ 구현 5단계에서 확인. v0.1 분리기가 만든 트랙 중 **지금 선택된 트랙**을 편집 대상으로 삼는다 |
| 8-4 | 이어보기 저장 시점 | ✅ **확정**: `time_pos` 는 매끄럽게 갱신된다(0.3초 간격 확인). 매초 쓸 이유가 없다 → **30초마다 + 파일 전환·종료 시** 저장 |
