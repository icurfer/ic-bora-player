# plan-v0.4.0 — 보면서 잘라낸다

`plan-v0.3.0.md`("보면서 배우는 도구")의 연장. 제품 정의는 그대로 두고 **한 갈래를 더 낸다**.

## §0 왜 편집기인가

v0.3 에서 이 앱은 "재생기"에서 "보면서 배우는 도구"가 됐다. 강의를 보며 메모하고, 구간을
반복하고, 핀을 꽂는다. 그 다음에 자연스럽게 따라오는 요구가 **"이 대목만 남기고 싶다"** 이다.

지금은 핀을 꽂아 놔도 그 대목을 다시 보려면 **이 앱에서 그 파일을 열어야** 한다.
4.4 GB 짜리 강의에서 3분짜리 핵심만 뽑아 두면 복습이 훨씬 싸진다. 그게 이번 갈래다.

- 강의에서 시험 범위 구간만 뽑아 따로 보관한다
- 여러 대목을 하나로 이어 복습본을 만든다
- 앞뒤 잡담·광고를 잘라낸다

**이미 절반은 있다.** 구간을 잡는 수단(A-B 반복, F5/F6)과 지점을 표시하는 수단(핀)이
v0.2~v0.3 에서 만들어졌다. 이번에 더하는 것은 **그 구간을 파일로 꺼내는 출구** 하나다.

### 0-1. 그래도 하지 않는 것

- **타임라인 편집기를 만들지 않는다.** 트랙·전환·자막 삽입·오디오 믹싱은 범위 밖이다.
  그건 Kdenlive 의 일이고, 그걸 이기려 들면 이 프로젝트가 죽는다.
- **인코딩을 직접 구현하지 않는다.** 전부 ffmpeg 에 위임한다 (헌법의 "재생 엔진을 직접
  구현하지 않는다"와 같은 이유).
- **원본을 건드리지 않는다.** 모든 출력은 새 파일이다. 덮어쓰기 경로를 아예 만들지 않는다.

## §1 실측이 정한 것 (2026-09-19)

전부 `../research/2026-09-19-video-cut-concat-tests.md` 에서 재현 명령과 함께 확인했다.

| 실측 | 설계 결론 |
|---|---|
| 무손실 자르기 0.08초, 그러나 30초 요청이 32.03초 | 빠른 길은 **정확하지 않다**. 두 모드를 다 준다 |
| 키프레임 간격이 1.0~4.4초로 가변 | 오차를 숫자로 약속하지 않는다. "장면 경계로 밀린다"로 설명 |
| 재인코딩은 정확하고 30초에 5.68초 | 정확 모드는 실용 범위 (실시간의 약 5배속) |
| 같은 소스 조각끼리는 0.11초 무손실 이어붙기 | **주 용도(한 강의 안에서 여러 대목)에는 빠른 길이 있다** |
| **코덱이 다르면 ffmpeg 이 조용히 깨진 파일을 만든다** | 앱이 **내보내기 전에 대조**한다 (§3-3) |

마지막 항목이 이번 기획에서 가장 중요하다. 자막 인코딩 문제와 같은 종류의 **조용한 실패**다.

## §2 무엇을 만드나 — 클립 목록

재생 중에 구간을 **목록에 담고**, 목록을 **한 번에 꺼낸다**. 담는 것과 꺼내는 것을 분리한 이유는,
강의를 보는 흐름을 끊지 않기 위해서다. 보면서 `K` 만 누르고, 다 본 뒤에 내보낸다.

### 2-1. 흐름

```
재생 중 ──[F5]── 시작 표시 ──[F6]── 끝 표시 ──[K]── 클립 목록에 담김 (토스트)
                                                        │
                        (계속 보면서 더 담는다)          │
                                                        ▼
                                          [Shift+K] 클립 목록 창
                                          · 순서 바꾸기 · 삭제 · 제목
                                          · 클릭하면 그 지점으로 이동
                                                        │
                                                    [내보내기]
                                                        ▼
                                    모드 선택 → 진행률 → 완료 토스트
```

`K` 를 누를 때 A-B 구간이 잡혀 있지 않으면 **현재 위치부터 30초**를 기본 구간으로 담는다.
(핀을 꽂듯 가볍게 쓸 수 있어야 한다. 구간은 목록 창에서 고치면 된다.)

### 2-2. 내보내기 선택지

| | 무엇을 하나 | 언제 |
|---|---|---|
| **하나로 합치기** | 담은 순서대로 이어붙여 파일 하나 | 복습본 만들기 (기본) |
| **조각별 저장** | 클립마다 파일 하나 | 대목별로 따로 보관 |

| 모드 | 어떻게 | 대가 |
|---|---|---|
| **빠르게** (기본) | `-c copy` | 즉시 끝남 · 경계가 장면 단위로 밀림 |
| **정확히** | 재인코딩 | 프레임 단위로 정확 · 실시간의 약 1/5 시간 |

## §3 설계

### 3-1. 배치 위치

새 모듈 `src/bora/clip/` — v0.3 에서 `stt/` `ai/` `notes/` 를 각각 폴더로 나눈 것과 같은 결.

| 파일 | 역할 |
|---|---|
| `model.py` | `Clip`(시작·끝·제목) 과 `ClipList`. 순수 데이터, GTK 의존 없음 |
| `probe.py` | `ffprobe` 로 스트림 정보를 읽고 **호환성을 대조**한다 (§3-3) |
| `runner.py` | `ffmpeg` 를 별도 프로세스로 띄우고 진행률을 받는다 |
| `dialog.py` | 클립 목록 창 + 내보내기 |

### 3-2. 설정·비밀값 보관 위치

**비밀값 없음.** ffmpeg 는 로컬 실행이고 네트워크를 타지 않는다.
클립 목록은 **저장하지 않는다** — 한 번 보는 동안의 작업물이고, 남기고 싶은 지점은 핀·메모가
이미 맡고 있다. 마지막 출력 폴더만 `state.py` 의 기존 설정에 얹는다.

### 3-3. 따르는 기존 패턴

- **별도 프로세스 + stdout 진행률** — `stt/runner.py` 와 같은 구조. 다만 STT 와 달리
  **별도 venv 가 필요 없다**. ffmpeg 는 이미 libmpv 의 동반 의존이라 항상 있다.
  진행률은 `ffmpeg -progress pipe:1` 의 `out_time_us` 를 읽는다.
- **취소 가능** — `ExtractRunner` 와 같이 `terminate()` 로 끊고 부분 파일을 지운다.
- **조용한 실패를 막는다** — 자막 로더가 인코딩을 판정하고 나서 mpv 에 넘기듯,
  내보내기 전에 `probe.py` 가 조각들의 `codec_name`·해상도·샘플레이트를 대조한다.
  하나라도 다르면 **빠른 모드를 막고** 정확 모드로 넘기며 그 이유를 화면에 적는다.

### 3-4. 자르기 명령

```
# 빠르게 — -ss 를 -i 앞에 둬 키프레임 탐색
ffmpeg -ss {start} -to {end} -i {src} -map 0:v:0 -map 0:a:{track} -c copy {tmp}

# 정확히 — 같은 구간을 다시 인코딩
ffmpeg -ss {start} -to {end} -i {src} -map 0:v:0 -map 0:a:{track} \
       -c:v libx264 -preset veryfast -crf 20 -c:a aac {tmp}

# 이어붙이기 (조각이 2개 이상일 때만)
ffmpeg -f concat -safe 0 -i {list} -c copy {out}
```

현재 선택된 오디오 트랙(`tracks.py`)을 따라간다 — 더빙 트랙을 골라 보고 있었다면 그게 딸려 나가야 한다.

## §4 성공 기준

| | 수용 테스트 |
|---|---|
| C1 | 재생 중 F5·F6 로 구간을 잡고 `K` 를 누르면 목록에 담기고 토스트가 뜬다 |
| C2 | 구간 없이 `K` 를 누르면 현재 위치부터 30초가 담긴다 |
| C3 | 클립 2개를 빠른 모드로 합치면 **재생 가능한** 파일이 나온다 (ffmpeg 디코드 검사 통과) |
| C4 | 정확 모드로 자른 조각의 길이가 요청과 **0.2초 이내**로 맞는다 |
| C5 | 내보내는 동안 진행률이 오르고, 취소하면 부분 파일이 남지 않는다 |
| C6 | 코덱이 다른 소스를 섞으면 빠른 모드가 막히고 이유가 화면에 보인다 |
