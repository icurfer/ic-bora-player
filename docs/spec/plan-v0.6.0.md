# plan-v0.6.0 — 윈도우에서도 쓴다

조사: [`../research/2026-10-03-windows-port-survey.md`](../research/2026-10-03-windows-port-survey.md)

## §0 왜 — 비목표를 뒤집는다

기획서 v0.1 §3 에 **"Windows·macOS 를 지원하지 않는다"** 를 비목표로 적었다. 근거는
"윈도우에는 이미 팟플레이어·곰플레이어가 있고 그것들이 국내 자막을 잘 다룬다" 였다.

**그 근거는 자막만 보고 한 말이었다.** 사용자의 말:

> 윈도우에서도 사용하고 싶다. 광고 그런 거 불편하고, 우리 플레이어처럼 유틸 기능들이 없다.

v0.3 부터 이 앱은 "보면서 배우는 도구"가 됐다 — 타임스탬프 메모, 핀, 구간 반복,
컷 편집, 음성 텍스트 추출, 메모에서 AI 질의. **그 기능들은 윈도우 플레이어에도 없다.**
그리고 국내 무료 플레이어의 광고는 학습 중에 특히 거슬린다.

비목표를 뒤집는다. 다만 **macOS 는 그대로 비목표**다(요구가 없고, 검증할 기기도 없다).

## §1 조사가 바꾼 판단

| 1차 판단 (2026-09-30) | 조사 후 |
|---|---|
| "GTK4+PyGObject 윈도우 배포는 별도 프로젝트급" | **과했다.** gvsbuild 가 GTK4·PyGObject·libadwaita·pycairo 를 한 묶음으로 준다 |
| "코드를 많이 고쳐야 한다" | **아니다.** 6,904줄 중 플랫폼에 묶인 것은 **약 150줄** |
| "윈도우엔 대안이 있으니 의미가 적다" | 자막만 보면 맞지만, **학습 도구 기능은 윈도우에도 없다** |

남은 진짜 위험은 하나다 — **GTK4(Windows)에서 GLArea + libmpv 렌더가 도는지 모른다.**

## §2 무엇을 만드나

**같은 코드 한 벌로 리눅스와 윈도우를 함께 돌린다.** 윈도우 전용 분기를 만들되,
분기 지점을 `platform/` 한 곳에 모아 본체가 플랫폼을 모르게 한다.

### 2-1. 들어가는 것

리눅스판과 **기능이 같다**. 재생·자막·메모·핀·구간 반복·타임라인 컷 편집.

### 2-2. 빠지는 것 (윈도우에서)

| | 왜 |
|---|---|
| 기본 영상 플레이어 설정 | `.desktop`·xdg 전제. 윈도우는 레지스트리라 별도 작업 — v0.6 범위 밖 |
| deb 패키징 | 당연히 안 쓴다. 대신 portable zip (§4) |

선택 기능(음성 텍스트 추출·AI 질의)은 venv 경로만 고치면 되므로 **넣는다.**

## §3 설계

### 3-1. 배치 위치

새 모듈 `src/bora/platform/` — 플랫폼이 갈리는 지점을 전부 여기 모은다.

| 파일 | 역할 |
|---|---|
| `__init__.py` | `IS_WINDOWS` 판정과 공통 진입점 |
| `gl.py` | GL 진입점 조회 — 리눅스 EGL / 윈도우 WGL (§3-4) |
| `paths.py` | 설정·캐시·데이터 폴더, venv 실행 파일 경로 |
| `integration.py` | 기본앱 설정 같은 데스크톱 연동 — 윈도우에선 비활성 |

기존 `util/gl.py` 와 `desktop.py` 는 여기로 옮긴다. **본체 코드에 `if windows` 를 흩지 않는다.**

### 3-2. 설정·비밀값 보관 위치

비밀값 없음. 경로는 전부 GLib 에 맡긴다 — `get_user_config_dir()`·`get_user_cache_dir()`·
`get_user_data_dir()` 가 윈도우에서 `%APPDATA%`·`%LOCALAPPDATA%` 를 올바로 돌려준다.
지금 `~/.local/share` 를 직접 조립하는 두 곳(`stt/install.py`, `ai/client.py`)을 고친다.

### 3-3. 따르는 기존 패턴

- **조용한 실패를 만들지 않는다** — 윈도우에서 못 하는 기능은 메뉴를 **끄고 이유를 적는다**.
  빈 창 컨트롤을 끈 것과 같은 결이다.
- **선택 기능은 별도 프로세스** — STT·AI 는 그대로. 경로만 `Scripts/python.exe` 로 갈린다.

### 3-4. GL 진입점 — 유일한 하드 블로커

```python
# 리눅스 (지금)
libEGL.so.1 / eglGetProcAddress

# 윈도우
opengl32.dll / wglGetProcAddress(name)
  → NULL 이면 GetProcAddress(opengl32, name)   # OpenGL 1.1 핵심 함수는 여기서만 나온다
```

`current_fbo()` 가 쓰는 `glGetIntegerv` 가 바로 1.1 함수다 — **폴백이 없으면 화면이
검게 나온다.** 리눅스에서 한 번 겪은 증상과 같은 모양이라 알아보기 어렵다.

> GTK4 가 윈도우에서 ANGLE(EGL)을 쓰도록 설정돼 있으면 EGL 경로가 맞다.
> 실기에서 `GDK_DEBUG=opengl` 로 확인하고 **둘 다 시도하는 폴백**으로 짠다.

## §4 배포

**portable zip 을 먼저 한다.** 설치 프로그램은 그 뒤에 본다.

```
bora-0.x.y-win64/
  python/          embeddable Python + 의존 패키지
  gtk/             gvsbuild 산출물 (GTK4·libadwaita·PyGObject)
  ffmpeg/          ffmpeg.exe, ffprobe.exe
  libmpv-2.dll
  bora.exe         런처 (환경변수 세우고 python -m bora)
```

압축을 풀고 `bora.exe` 를 누르면 돌아가는 것이 목표다. 설치·관리자 권한·레지스트리 없음.

> gvsbuild 는 배포용으로 직접 빌드를 권한다. 1차는 공식 zip 으로 **동작을 확인**하고,
> 배포본은 CI 에서 빌드할지 정한다(§6 위험).

## §5 성공 기준

| | 수용 테스트 |
|---|---|
| W1 | 윈도우 11 에서 zip 을 풀고 `bora.exe` 로 **영상이 재생된다** |
| W2 | CP949 `.smi` 가 설정 없이 한글로 나온다 (리눅스 T1 과 같은 표본) |
| W3 | 하드웨어 디코딩이 붙는다 (`hwdec_current` 가 `no` 가 아니다) |
| W4 | 메모에 **한글을 IME 로 입력**하고 저장·재열기가 된다 |
| W5 | 타임라인을 열면 필름스트립이 채워지고 자르기·내보내기가 된다 |
| W6 | 윈도우 10 에서도 W1~W5 가 된다 |
| W7 | **리눅스 회귀 없음** — 기존 시나리오 11개가 그대로 통과한다 |

W7 이 가장 중요하다. 윈도우를 얻겠다고 리눅스를 깨뜨리면 안 된다.

## §6 위험

| 위험 | 크기 | 대응 |
|---|---|---|
| **GLArea + libmpv 가 윈도우에서 안 돈다** | 🔴 치명 | **스파이크를 맨 앞에 둔다**(§7-1). 막히면 기획을 다시 쓴다 — 별도 GL 컨텍스트 + 텍스처 복사가 차선 |
| gvsbuild zip 재배포의 법적·보안 책임 | 🟡 보통 | 1차는 동작 확인용. 배포본은 CI 빌드를 검토 |
| 배포 크기 (GTK+Python+ffmpeg 합쳐 수백 MB) | 🟡 보통 | portable zip 이라 감수. 선택 기능(STT 모델 436MB)은 여전히 따로 |
| libadwaita 가 윈도우에서 이질적 | 🟢 낮음 | 기능이 목적이지 외관이 목적이 아니다. 불만이 나오면 그때 |
| 두 플랫폼 유지비 | 🟡 보통 | 분기를 `platform/` 한 곳에 가둔다. 검증은 리눅스 CI + 윈도우 수동 |

## §8 폴더 구조 (2026-10-03 적용)

플랫폼별 폴더로 나눴다. macOS·Android 는 **자리와 설명만** 있고 구현은 없다.

```
src/bora/platform/
  base.py        각 폴더가 지켜야 할 이름과 뜻 + 공통 기본 구현
  __init__.py    런타임에 하나를 고른다 (IS_LINUX / IS_WINDOWS / IS_MAC / IS_ANDROID)
  linux/         ✅ 실기 검증 (Ubuntu 26.04)       gl=EGL,  integration=xdg
  windows/       🚧 코드는 있으나 미검증            gl=WGL+폴백, integration=없음
  macos/         📋 뼈대만, 조사 안 함              gl=미구현(OpenGL deprecated)
  android/       📋 자리만 — 사실상 새 프로젝트      gl=의미 없음(GTK 미지원)
```

각 폴더는 `gl`·`paths`·`integration` 세 모듈을 같은 이름으로 제공한다.
`tests/test_platform.py` 가 **네 플랫폼 전부**에 대해 이름이 빠지지 않았는지,
지금 플랫폼이 아니어도 import 가 되는지 검사한다(25건).

### 안드로이드에 대한 정직한 평가

GTK 는 안드로이드를 지원하지 않는다. UI 를 통째로 새로 짜야 하고(터치·세로 화면),
파이썬도 끼워 넣어야 하며, 파일 접근이 경로가 아니라 SAF URI 다.
**가져갈 수 있는 것은 로직층 약 2,500줄**(자막 725줄이 핵심)이고, 현실적인 길은
Kotlin 앱 + libmpv 에 자막 로직을 포팅하거나 Chaquopy 로 끼우는 것이다.
`platform/android/__init__.py` 에 같은 내용을 적어 뒀다.
